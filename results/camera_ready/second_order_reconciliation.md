## Explanation

1. **The 11% is mostly noise in the FD reference, not polynomial error.** On the sweep's own points the same polynomial has normalised error 10.9% (r = 0.64) against raw FD and 3.4% (r = 0.91) against the smoothing spline. The FD reference is itself 9.1% off the spline (same normalisation).
2. **Cause: table quantisation.** 38% of the G values are rounded to 1 J/mol (|G| >= 1e5). A 3-point second difference with a 10 K step multiplies that by about 1/h^2: predicted rms noise 0.0043 J/(mol K^2) with the true per-value quantum, observed rms(spline - FD) 0.0044, against mean abs d2G/dT2 of 0.027. Squared errors add: rms(P - FD)^2 = rms(P - spline)^2 + rms(spline - FD)^2 (cross-correlation -0.004); the FD noise carries 85% of the squared P-vs-FD error.
3. **Dose-response.** Stencils whose three values are all on the 0.01 J/mol quantum (61% of points): 3.6% vs FD, 3.5% vs spline. Stencils touching a 1 J/mol value: 24.5% vs FD (r = 0.04) but 3.1% vs spline. Widening the stencil to m = 5 (50 K half-width) takes P-vs-FD from 10.4% to 2.6%, which is the P-vs-spline value (2.7%) within the spline-vs-FD residual (0.6%); the truncation proxy stays at 0.18% of mean abs G''. This second route uses raw data only, so the ~3% is not an artefact of the smoothing spline's own bias.
4. **Normalisation and point set are minor.** Mean-abs normalisation vs the Newton per-point relative error: 3.4% vs 3.0% (Cp, spline, grid). d2G/dT2 vs Cp: 3.4% vs 3.2%. Adding a = dt*kappa to Cp in the denominator (Jacobian) changes the grid/spline mean from 3.02% to 2.99% (Cp ~ 38 J/mol/K dwarfs a). Moving from the grid to the Newton reference path (off-grid, 1800 -> 1050 K) gives 3.19% Jacobian error against the Newton script's stored 3.07% (`newton_summary.csv`, Polynomial, protocol random). The path is off the 10 K grid and weights temperatures by where the reference trajectory spends its steps, so it is a different average from the grid (grid T >= 1050 K, spline: 3.0%; path: 3.8%); this residual difference was not decomposed further.

## Bug in the sweep's error budget (existing outputs not modified)

`run_calphad_second_derivative_fd.py` sets G_ROUND_SIGMA = 0.01/sqrt(12) for every value, so `fd_rounding_rms` in `derivative_second_order*.csv` is 7.1e-05 for d2/dT2, 61x below the quantum-aware 0.0043. Its `rounding_over_mae` / `flag_fd_limited` therefore under-report, and the same `0.01` assumption is likely to affect the d2/dc2 and d2/dTdc rows too (not checked here). The FD d2G/dT2 error of ~11% is a measurement floor of the reference, not a model deficiency; the paper should report the spline- or wide-stencil-referenced value (or both) next to it.

## Caveats

- The spline truth is a per-composition degree-4 smoothing spline (interior knots at most 12); agreement with the polynomial may partly reflect shared smoothness. The wide-stencil FD in section 3 is the independent check.
- Seeds vary only the polynomial fit; the references and point sets are seed independent, so the ± is fit-to-fit variation only.
- Only the `random` protocol and the all-grid point set are used (the sweep's held-out-only subset is not re-run here; see `derivative_second_order_summary.csv`); the Newton `temp_band` Jacobian error is not reproduced here.
